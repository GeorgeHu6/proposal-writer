# 正式申报语体与填写提示

## 成稿的表达目标

正式申报书直接讲项目：研究什么、采用什么方法、如何实施、形成什么成果、怎样评测。采用明确主体、具体动作和清晰因果关系的连续论述。章节联系通过技术对象、输入输出、成果和阶段安排体现，术语和名称保持一致。

句子基本结构为“研究主体或对象—研究动作—技术过程—预期作用”。未来研究使用“拟研究”“研究”“构建”“形成”“开展”等符合项目阶段的动词，结论与事实依据对应。

## 正面组织每一类内容

| 内容 | 成稿写法 |
|---|---|
| 成果用途 | 说明成果由谁使用、进入哪个业务环节、提供什么数据或技术能力 |
| 适用范围 | 写明研究场景、对象、数据条件、实验条件和使用范围 |
| 技术局限 | 描述具体困难、作用机制、影响和拟研究的解决方法 |
| 风险对策 | 说明风险来源、识别信号、影响任务与处置过程 |
| 数据与权限 | 说明授权范围、访问分级、审核主体和使用流程 |
| 知识产权 | 说明登记、权属、许可、署名、转化及各方协商程序 |
| 指标与验收 | 说明测试条件、计算方法、比较对象、判断依据与证明材料 |

正式正文采用上述具体叙述。将限制性套话、否定式管理口吻、写作提醒和免责表述改写为项目的实际安排。这项要求适用于目录、正文、图表题、表头、单元格和页眉页脚，覆盖“仅提供参考”“不能直接替代”“不能据此推定”“不得……”“不将……”及同类变体。

成稿中工作流程说明、读者提醒和撰写建议由括号填写提示或工作记录承载。抽象字母标签采用具体中文名称表达；正常的课题编号、指标1.1、图2.1、文献[1]和科学符号正常使用。

科学含义保持准确。技术条件使用“在……条件下”；研究范围使用“研究对象为……”或“适用范围为……”；真实的缺测、非线性、不确定性、不可辨识性等科学概念按研究需要保留。通过描述变量、机制和实验条件陈述技术局限，通过具体处置措施陈述风险。

## 填写提示完整放入中文方括号

依赖真实情况的信息用【请填写……】或【请补充……】占位。所需事实、数据来源、填写口径、填写方法、核实建议和确认事项均完整写在同一组【】内。括号外继续正式项目叙述。

| 项目实际信息 | 填写提示 |
|---|---|
| 指南关联 | 【请填写专项名称、申报年度、指南方向和具体条目，并说明各条目对应的任务与指标】 |
| 指标数值 | 【请填写预警准确率目标值、现有基线、样本范围和计算口径，并附对应测试资料】 |
| 研究条件 | 【请填写实验平台、可用设备、数据来源及使用授权范围】 |
| 实施周期 | 【请填写总周期、起止时间、中期检查节点及各阶段日期】 |
| 单位职责 | 【请填写牵头单位和参与单位在技术协调、数据提供与验证中的具体职责】 |
| 示范合作 | 【请填写示范地点、合作单位、部署条件与合作依据，并核实相关协议】 |
| 权益约定 | 【请填写各方约定的成果权属、署名规则、许可方式和收益分配原则或比例】 |
| 量化效益 | 【请填写测算规模、单位成本、改善幅度及其统计年份和来源，并说明计算过程】 |
| 现状引文 | 【请补充支持本项技术比较的原始论文、发布机构、年份、实验条件及具体结果】 |

填写提示承载实际缺口与填写方法，已具备依据的事实及可设计的技术方案写为完整正文。占位范围与事实缺口相对应；一个缺口可用一个完整提示说明所需内容。各章通用研究内容与实施程序照常展开。

## 句式改写示例

以下左列用于识别工作稿中的问题句式，右列为项目叙述的改写方向；具体技术名、主体与条件应按实际方案填写。

| 待改表达 | 正式项目叙述 |
|---|---|
| 仿真结果仅提供参考，不能直接替代现场决策 | 仿真结果用于比较控制方案的运行效果，现场调度依据实测交通状态、设施约束与经审定的处置流程执行。 |
| 不能据此推定系统达到考核要求 | 系统性能按照规定测试集、场景条件和指标计算方法开展测评，形成对应测试记录和验收材料。 |
| 未经许可不得对外使用成果 | 成果对外使用按合作协议确定的许可范围和审核程序执行。【请填写许可范围、审核主体及授权流程】 |
| 不将试点效果直接外推到全部场景 | 研究覆盖【请填写研究场景与适用范围】，通过跨区域和跨工况测试分析场景变化对技术效果的影响。 |
| 请根据实际情况补充合作单位和分工 | 【请填写合作单位及各方在数据提供、算法研究、系统开发和应用验证中的具体任务】 |
| 本段需要在正式申报前由相关方确认 | 【请填写合作各方确认的相关条款，并依据已签署协议核实条款内容】 |
| P1对应G1，先冻结指标口径 | 针对观测缺失引起的状态估计误差，研究多源观测融合方法，通过状态误差与稳定性测试评价研究效果。 |

正面改写保留原有科学条件、权利约定和验证要求。事实缺口以具体占位表达，生成说明和写作提醒在工作记录中处理。

## 两次检查

完成内容与逻辑审查后，使用formal_style.py识别工作稿中的明确句式与括号外填写建议；生成Word后，回读实际DOCX再检查正文、表格、页眉页脚和脚注尾注。根据命中位置修订具体句子，再执行检查。

程序识别明确词句及部分变体；逐句审查同时关注含义相同的表达。通过具体技术内容完成改写，确保科学事实与实际约定得到保留。
