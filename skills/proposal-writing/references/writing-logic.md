# 章节联系和写法

## 全篇主线

项目的应用需求和现状不足引出科学问题及技术瓶颈；研究目标说明要解决到什么程度；研究内容和方法说明具体路径；课题分解落实研究安排；创新点概括方法上的新增；指标与进度说明如何分期验证；保障和风险对策支持上述路径的实施。

内部审查可建立中文对应表，使用“现状不足、关键问题、目标、课题、方法、成果、指标、验证、阶段”等列名。正式正文使用具体名称，不将抽象字母编号或内部审查表替代论证。

## 第一部分如何支撑第二部分

国内外现状按与项目研究方向一致的技术主题组织。介绍代表方法之后说明其适用条件、已解决的问题及剩余困难；综合比较后提出本项目的技术切入点。这些不足应分别在第二部分的关键问题、目标和研究任务中得到回应。

不能用宏观政策意义替代技术差距分析；也不能先写一段通用现状，再在后文突然增加现状中从未讨论的新研究主线。确需新增方向，应同步补充其需求和技术依据。

## 第二部分各章如何对应

| 栏目 | 论证职责 | 与后续内容的联系 |
|---|---|---|
| 指南关联 | 对照实际指南说明研究范围和要求 | 指南中的任务及指标在目标、课题和测评中逐项落实 |
| 目标及考核指标 | 写明预期获得的知识、技术能力和效果 | 每个目标有研究内容、成果和测评方法支撑 |
| 成果呈现 | 说明模型、算法、系统、数据、规范或报告的交付形态 | 与总指标、分课题成果和阶段交付名称一致 |
| 主要研究内容 | 提炼科学与技术问题，组织研究对象和内容 | 由研究方法解释实现机制，由课题分解落实承担环节 |
| 研究方法 | 解释输入、模型、算法、作用机制、实现过程和验证方案 | 每项关键方法支持某项研究任务和指标 |
| 课题分解情况 | 说明分解依据和课题之间的技术关系 | 每个课题的输入来源、成果去向与集成作用清楚 |
| 各课题内容 | 将总体方案细化到具体子任务 | 分课题目标与指标覆盖总体目标，公共成果不重复计数 |
| 创新点 | 相对于现有技术说明实质新增 | 在前述研究内容中有明确安排，并能通过实验比较验证 |
| 预期效益 | 说明成果如何进入实际业务并产生价值 | 由已描述的技术效果和应用方案推导，不凭空给收益数字 |

项目层概述统领方向，课题层细化对象、变量、过程与交付。不要把总体研究内容原文复制到每个课题，也不要每个课题各自从数据采集重复建设到完整平台。

课题关系应具体说明，例如“风险预测课题接收状态估计课题输出的状态和置信信息，形成预测结果供调度课题使用；集成验证结果反馈修正状态模型和预测参数”。适量使用承接句即可，避免把“协同、赋能、闭环”等词当成关系说明。

## 第四部分如何承接第二部分

沿用第二部分的课题、子任务、成果和指标名称安排阶段。数据与规范先于模型训练，原型先于联调，模块成熟后开展集成和场景验证；并行研究需解释共享条件。每阶段明确研究工作、成果状态、测评方式和下一阶段输入。

总体指标、分课题指标和阶段指标的数值、单位和测量口径应一致。误差或时延等越小越好的指标，其阶段改善方向要正确。未知周期和日期留具体填写提示，不强行套三年期计划。

## 第五部分如何支持前文

实施机制针对跨课题接口、进度衔接、数据共享和成果质量提出具体安排；保障措施对应方法所需的数据、设备、实验和应用条件；成果管理围绕第二部分的实际交付物设计登记、保护和转化程序；风险分析针对前述方法、接口、数据与场景中的实际困难提出识别信号、缓解措施和备选方案。

单位名称、已有资源和合作约定需要真实资料。先写可设计的机制，再在对应位置以【请填写……】提示补充具体条件，不以“信息不足”等理由删除已保留栏目。

## 章节内的分层逻辑

每个父标题先有中心说明，下级标题分别回答其组成问题。一般按研究对象或技术任务划分并列层次，再按机理、方法、实现和验证展开，避免同层混列“科学问题、一个算法名、平台页面、社会效益”。一个小节围绕一个明确论点形成连续段落，表格用于对比与汇总，不替代完整研究论述。

科学问题解释未知机理与规律；技术问题解释约束条件下的能力瓶颈；工程任务形成具体系统或验证环境。正式语体保留“拟研究”“通过……构建……”等未来研究表达，避免无依据的成功承诺。

## 成稿的承接表达

章节承接直接说明具体技术内容，例如“状态估计结果进入风险预测模型，预测结果及设施约束共同构成调度优化的输入”。研究适用范围由场景、对象和测试条件表述，成果用途由业务环节与使用方式表述。实际合作、资源和测评资料的位置用【请填写……】提示，填写建议与核实方法一并置于括号内。
