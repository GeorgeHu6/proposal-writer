# Word交付说明

## 层级是本次排版重点

以用户指定的重大专项目录生成可编辑DOCX。项目名称为Title；四个部分为Heading 1；“一、二、三”等章为Heading 2；“（一）（二）”节为Heading 3；课题及更细的研究内容使用Heading 4—6。每一层均有相应的Word大纲级别，可在导航窗格浏览，字体大小、段前距与缩进作适度区分。

第一、第二、第四、第五部分保留原编号；第三部分不生成。四个部分可另起页以便识别，不设置第三部分空白页。正文为原生段落，表格为原生表格，不设写保护，不以整页图像替代。未知实际信息的【请填写……】保留为可编辑文字。

默认不单列封面、摘要、目录、参考资料顶层部分或核查附录，不写“名称驱动初稿”等状态行。参考文献如需列出放在第一部分末尾的下级栏目。正文直入既定四个部分。

只要求清晰易读的标题层级与基本段落排版，不追求严格字号、字体、页边距和分页细节。用户追加模板要求时优先按其指定处理。不要把过程说明放进正式文件。

## 内置生成器

优先使用当前环境文档技能或工具，也可运行：

```text
<环境Python> <技能目录>/scripts/build_docx.py --input <工作目录>/proposal.json --output <交付目录>/项目名称_申报书正文.docx
```

完整输入结构见 [目录模板](../templates/major-program.json)。将模板中需要撰写的技术内容替换为完整正文；只有依赖真实具体资料的缺口保留填写提示。

`profile` 默认为 `major-program`，检查四部分和必需章节目次；只有用户明确要求其他目录或单节文档时才使用 `custom`。完整稿不得通过custom绕过本次目录要求。

每个 `sections` 项为一个部分，`heading` 是完整标题，`blocks` 中按顺序放标题、段落和表格。标题块支持2—6级，不能向下跳级；正文块支持paragraph、bullet，表格块支持table。表格行列对应，最多六列，宽矩阵按相同成果名称或正常指标编号拆表。

生成器在Word导出前执行proposal_contract.py的目录、层级与典型用语检查。不符合要求时报告具体位置，先修改工作稿再生成，不提供绕过语体检查的开关。程序只能检查明确规则，不能判断事实正确性或研究论证充分性。

1.4.0版使用formal_style.py统一检查正面直接的申报表达和【】填写提示。生成前核查工作稿；生成后回读实际DOCX，检查正文、表格、页眉页脚、脚注尾注的文字。命中句式时按具体项目含义改写，填写事项及建议完整放入【】；再次检查通过后发布最终Word。内置生成器先将文稿存入临时文件，检查通过后再保存到最终位置，已有交付文件在检查失败时保持原状。

其他文档工具生成的Word也执行同一终稿回读步骤：

```text
<环境Python> <技能目录>/scripts/formal_style.py --docx <实际Word路径> --report <工作目录>/终稿语体核查.json
```

检查报告在工作目录保存，正式申报书呈现项目内容及对应的【填写提示】。研究条件和真实风险用具体机制、变量、适用范围与应对措施正面陈述。

同时执行word_limits.py的章节篇幅检查，默认标准见word-limits.md和word-limits.json。未满足实际适用的章节范围时不导出Word。可先单独检查并将统计报告保存到工作目录：

```text
<环境Python> <技能目录>/scripts/word_limits.py --input <工作目录>/proposal.json --report <工作目录>/字数核查.json
```

正文汉字按章节树汇总，父项包含下级内容但全篇不重复累计。表格文字、【填写提示】、标题、参考文献不替代叙述；图题或文献条目若以paragraph块出现，应设置role为caption或reference以便排除。不要给正常正文设置这些角色来规避篇幅要求。用户明确要求不同字数时，length_requirements的填写方法见word-limits.md。

可单独检查输入：
```text
<环境Python> <技能目录>/scripts/proposal_contract.py --input <工作目录>/proposal.json
```

## 交付前

重新打开Word，检查四部分、各级标题、全部段落和原生表格存在，无写保护，且没有第三部分。按文档技能渲染并查看页面，修复缺字、截断或溢出，不为装饰细节过度调整。交付Word链接，过程JSON、程序、PDF和页面预览默认不交付。

文件生成依赖环境文档工具或Python与python-docx，插件没有独立托管文档服务。确实不能生成时如实向用户说明，不把这类工具说明写入项目正文。
